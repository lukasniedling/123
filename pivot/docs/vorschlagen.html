Worum es geht

vorschlagen.html ist das Kontaktformular: Besucher schlagen einen Ort vor oder stellen eine Frage. Rechts daneben zeigt eine eingebettete OpenStreetMap-Karte (iframe) die Innenstadt.

Die Seite hat alle drei Stufen: V1 das Formular mit den Prüfungen des Browsers (required, minlength, pattern …); V2 js/formular.js zeigt freundliche Fehlermeldungen, zählt die Zeichen und erklärt, dass Senden per Doppelklick (file://) nicht geht; V3 php/vorschlag.php nimmt das Formular auf dem Server an, prüft alles noch einmal und speichert es in daten/vorschlaege.json. Stile: css/formular.css.

Vorschlag für die Präsentation: Lukas Niedling (Tests und Präsentation) zeigt Formular, Prüfungen und iframe; den PHP-Teil (php/vorschlag.php) erklärt Anes Sahbegovic (Programmierung). Die ganze Aufteilung steht im Überblick.

Fragen, die kommen können

Was ist der Unterschied zwischen get und post?
Bei get stehen die Felder in der Adresse (sichtbar, im Verlauf gespeichert, kurz). Bei post stehen sie im Inhalt der Anfrage. Für ein Formular mit Name und E-Mail ist post richtig.
Warum prüft der Server noch einmal, wenn der Browser schon prüft?
Die Prüfung im Browser lässt sich umgehen (Entwicklertools, eigene Anfragen). Nur was der Server prüft, ist sicher.
Warum kann man das Formular per Doppelklick nicht senden?
Dann fehlt ein Webserver, der PHP ausführt. Der Browser würde nur den Programmtext von vorschlag.php zeigen. Mit XAMPP unter http://localhost/ klappt es.
Wozu das iframe, und was hat es mit Datenschutz zu tun?
Es zeigt eine echte Stadtkarte zur Orientierung. Beim Laden verbindet sich der Browser mit den Servern von OpenStreetMap und überträgt die IP-Adresse; das steht in der Datenschutzerklärung und im Hinweis unter der Karte.
Warum ein Inline-Stil, wenn doch alles in CSS-Dateien steht?
Als Beispiel für die Übung „Inline-Verfahren“: Ein style-Attribut gilt nur für ein Element und überschreibt die Regeln der Dateien. Für eine ganze Website ist das unpraktisch, deshalb nur dieses eine Mal.
