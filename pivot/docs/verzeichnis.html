Worum es geht

quadrate.html listet alle 146 Quadrate in einer Tabelle: Lage, Art (Gebäude, Platz, Park), die Zahl der Orte je Kategorie und einen Link zur Karte. Über der Tabelle stehen eine Sprungliste zu den Reihen A bis U und (mit JavaScript) ein Suchfeld.

Die Seite wird nicht von Hand geschrieben: tools/export_verzeichnis.py liest js/data/quadrate.js und js/data/orte.js, zählt die Orte und schreibt die fertige Tabelle als HTML. Deshalb funktioniert die Seite schon ohne JavaScript (V1). js/verzeichnis.js fügt in V2 nur das Sortieren und die Suche hinzu; Stile stehen in css/verzeichnis.css.

Vorschlag für die Präsentation: Matti Katila (Inhalte und Anforderungen). Die ganze Aufteilung steht im Überblick.

Fragen, die kommen können

Was ist der Unterschied zwischen th und td?
th ist eine Kopfzelle (fett, mit scope für Spalte oder Zeile), td eine normale Datenzelle. In unserer Tabelle ist der Code jeder Zeile (A1) eine Kopfzelle der Zeile.
Wie funktioniert der Sprung zur Reihe G?
Der Link hat href="#q-G1", die Tabellenzeile hat id="q-G1". Der Browser scrollt zur Zeile, :target färbt sie gelb. Kein JavaScript nötig.
Warum steht die Tabelle fertig im HTML und wird nicht von JavaScript gebaut?
So ist sie ohne JavaScript vollständig (V1), Suchmaschinen und Screenreader sehen sie sofort. JavaScript sortiert und filtert nur die vorhandenen Zeilen.
Warum sortiert „L10“ nach „L9“?
Weil localeCompare mit numeric: true Zahlen im Text als Zahlen vergleicht. Ohne diese Option käme „L10“ vor „L2“.

Versionen

V1 die fertige Tabelle mit Sprungliste. V2 js/verzeichnis.js: Sortierknöpfe in den Spaltenköpfen und Suchfeld (im HTML mit hidden versteckt, das Skript zeigt es). Die Links „Auf der Karte“ öffnen das Quadrat erst ab V2; in V1 zeigen sie die Startseite.
